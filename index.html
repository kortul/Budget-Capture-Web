05 / PORTABILITY

Data & backup

Your finance data is contained in the database file you open and save. The website has no account and no server-side storage.

Categories & Numbers profile

Your category groups and Numbers table captions are stored inside the open `.budget` database. They are not part of the website code.

Categories already used by transactions are retained as Other if removed from a group, so existing records and rules are not deleted.

Own SBP transfer name markers

Names in your own outgoing/incoming SBP transfers. These markers are stored only inside this database file. Existing Windows databases are pre-filled from already recognised internal transfers.

Database file

Open the existing Windows SQLite database directly, or create a new `.budget` file. All changes stay in browser memory until you save.

No database open.

Import an old Windows JSON backup

Use this only if you exported Download database JSON from Windows. This merges the rows into the open web database. Direct SQLite opening is preferred.

Privacy

  • Statements are parsed inside this browser.
  • The `.budget` SQLite file stays on your device / chosen cloud drive. Open the same file in Financial Analytics on any computer to read the reports.
  • GitHub Pages serves only the app code and static assets.
  • Pinned runtime libraries load only from this GitHub Pages origin; there are no third-party CDN fallbacks or external data connections.
  • Do not add `.budget`, `.sqlite3`, `.db`, PDF or XLSX financial files to the Git repository.

Supported files in this browser release

  • Sber Online History print PDF (the newer iPhone/Safari export).
  • Yandex Bank payment-account and Сейв savings statement PDFs.
  • T-Bank transaction-history Excel (.xlsx).
  • Raiffeisen statement CSV.
  • Existing Budget Capture SQLite database and v1.x database JSON backup.

Legacy Sber card PDFs, scanned/image-only PDFs, OCR and local Ollama are not yet ported to this static web build.
